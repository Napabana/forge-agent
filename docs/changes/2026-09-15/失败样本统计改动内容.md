# 失败样本统计改动内容

## 本轮目标

对已有 Trace 中 provider 空响应和模型误把 `finish` 当工具的样本做首轮事实统计，判断
是否已有足够证据修改恢复策略。

## 数据范围与方法

- 数据源：仓库 `logs/` 下现有 22 个 JSONL 文件。
- provider 空响应：匹配 `Model stopped with no content`，再读取对应 Run 的最终事件。
- `finish` 误调用：匹配 `Unknown tool 'finish'` Observation，再核对最终任务状态和原因。
- 只统计命中文件和结构化终态，不输出完整模型内容，也不读取配置或秘密。

## 真实结果

- provider 空响应：命中 1 个 Run，`712e643c_20260915_040004`；最终 `task_failed`，5 steps。
- `finish` 误调用：命中 3 个 Run：
  - `873e6ee9_20260914_112807`：最终 `task_complete`，6 steps。
  - `80b7bd15_20260915_035408`：最终 `task_failed`，10 steps；失败原因是最新 test 未通过，
    已由真实 PR 案例定位为工具 cwd 错误，不归因于 `finish` 误调用。
  - `297cb818_20260915_040600`：下一步恢复为结构化 finish，最终 `task_complete`，8 steps。

文本短语在同一 Trace 中可能同时出现在 Action 和终态 reason，因此报告以“命中 Run”而
不是文本出现次数为准。

## 决策

- 现有 22 个 Trace 来自不同任务、模型上下文和运行阶段，1/22、3/22 不能称为模型失败率。
- `finish` 误调用已有 2 个自然恢复样本，没有证据支持新增专用工具或改变协议。
- provider 空响应只有 1 个样本，先在固定任务集中继续记录，不因单例增加重试状态机。
- 本轮不修改生产代码、不引入 multi-tool call、不增加依赖。

## Git 与测试

- 本轮统计只读取 JSONL，并更新被忽略的 Markdown；未修改代码，因此未运行新测试。
- 同一轮此前完成的 `--no-pr` 参数化契约结果为 2 passed in 2.34s。
- `config/default.yaml`、Forge SSH remote 与 `stash@{0}` 均未修改。
