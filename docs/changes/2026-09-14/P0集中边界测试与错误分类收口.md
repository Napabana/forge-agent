# P0 集中边界测试与错误分类收口

## 目标与结论

本轮执行批次 C，只补 P0-1、P0-2 和最小 Trace v2 的集中边界测试，以及测试直接
暴露的两个小型生产缺口。没有开始 P1 Runner，也没有运行仓库全量测试。

## 修改

- `tests/test_prepare_next_turn.py`
  - 验证未配置 callback 与返回 `None` 的请求 history 一致。
  - 验证 callback 异常后不再调用 LLM，并产生带异常类别的 failed Trace。
  - 在一个测试中覆盖 callback 前取消和 callback 执行期间取消。
- `tests/test_harness.py`
  - 验证类型化 block 与旧字符串 block 的兼容语义。
  - 验证 Pre Hook 异常 fail-closed，Post Hook 返回值不改写工具结果。
  - 验证 unknown、permission、timeout、infrastructure 和 tool exception 分类。
- `tests/test_trace_v2.py`
  - 验证 Post Hook 观察异常不会破坏工具结果，但会进入 Tool Trace diagnostics。
  - 验证 MockBackend input/output usage 同时进入调用 Trace 和 Run 汇总。
  - 验证 Trace 写入失败只产生 warning，不覆盖成功的 Agent 结果。
- `harness/executor.py`、`tools/base.py`、`agent/core.py`
  - 在统一 executor 层给尚未分类的工具失败补充 timeout、infrastructure 或
    tool_execution 类别，避免逐个修改工具。
  - `ToolResult` 增加只读语义的 diagnostics 元数据；Post Hook 异常写入诊断，
    Agent 将其放入 Tool lifecycle Trace，不改变 Observation 成败和输出。
- `TODO-P0-P1.md`、`AGENTS.md`
  - 只勾选已有实现且本轮得到测试证据的条目。

未修改 `config/default.yaml`。

## 测试

Windows Python 3.12.14，使用项目 `.venv` site-packages：

```text
pytest tests/test_prepare_next_turn.py tests/test_harness.py tests/test_trace_v2.py -q
```

首次集中运行收集 35 项，结果 **34 passed、1 failed（2.73s）**。失败来自测试将动态
Repo Map system prompt 一并比较：第一次运行产生的日志目录改变了第二次仓库扫描结果，
并非 callback 改变 history。测试收窄为比较 system prompt 之后的请求消息，然后只
重跑该节点，结果 **1 passed（0.86s）**。

遵循用户减少重复测试的要求，没有再次运行全部 35 项。准确结论是首次通过的 34 项和
修正后的单节点分别通过，不将其表述成一次完整 35 passed，也没有声称全量回归通过。
