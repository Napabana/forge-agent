## 行为变化

- Completion Guard 使用稳定 reason code：`REQUIRED_CHANGE_MISSING`、
  `REPOSITORY_UNCHANGED`、`REQUIRED_TEST_MISSING`、`LATEST_TEST_FAILED`、
  `FINAL_STATE_UNVERIFIED`。可恢复拒绝写入 canonical History 和
  `completion_rejected` Trace 后继续执行。
- hard ceiling 返回 `INCOMPLETE + resource_exhausted/max_steps`；Loop Detector 返回
  `INCOMPLETE + loop_detected`；显式 GIVE_UP 保持 `GAVE_UP + agent_gave_up`。
- Provider/基础设施/内部错误仍为 `FAILED`；取消为 `CANCELED + canceled`；成功为
  `SUCCESS + completion_satisfied`。
- 最后三步统一使用 ephemeral `[RESOURCE BUDGET LOW]`，不显示精确步数且不进入 History。
- Runner 仅对 `SUCCESS` 执行独立 acceptance；非成功 delivery 路径继续被阻断。
- B2 JSONL/report 新增 input/output token、termination/resource reason、completion
  rejection 统计、逐样本证据和 v2→v3 逐格对照，并兼容 v2 `max_steps` 行。

## B2 v3 完整 9-run

| variant | strict pass@1 | verifier pass | mean input | mean output | mean total（含 semantic） | mean latency |
|---|---:|---:|---:|---:|---:|---:|
| baseline | 1/3 | 2/3 | 120,777 | 2,247 | 123,024 | 267.3s |
| pruning | 2/3 | 2/3 | 98,486.3 | 2,106 | 100,592.3 | 250.9s |
| hybrid | 2/3 | 3/3 | 51,262.7 | 1,867.3 | 62,157.7 | 108.0s |

- completion rejection：hybrid `huge-tool-history` 出现 1 次 `LATEST_TEST_FAILED`；样本后续
  继续执行，但最终仍为 `INCOMPLETE/max_steps`，verifier passed。
- commit-aware 污染：v2 的 long/hybrid 与 huge/baseline 均为 verifier passed 但旧 guard
  FAILED；v3 两格均为 SUCCESS，说明本次样本中该误判不再出现。
- `superseded-state`：hybrid 和 pruning 为 SUCCESS；baseline 仍为 verifier passed 但
  `INCOMPLETE/max_steps`，因此该现象未在所有策略上消失。
- v2→v3 strict：baseline 0/3→1/3，pruning 1/3→2/3，hybrid 1/3→2/3；这些变化同时受
  termination 修复和模型非确定性影响，不能做单因果或泛化结论。

## 实验边界

- 每个 variant 只有 3 个 case、每格 1 次；模型非确定性明显。
- 一次 hybrid 请求发生临时 500，沿既有固定请求级 retry 成功恢复；未重跑样本。
- context `budget_tokens=8000` 是单次请求上下文预算，不是 run 总 token hard limit。
- 未实现总 token、wall-clock、cost Resource Manager，也未向 Agent 反馈 hidden verifier。
