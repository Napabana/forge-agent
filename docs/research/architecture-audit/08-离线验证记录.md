## 2. 原型接口和判断语义

`evals/completion_candidate_probe.py` 是一个**独立且没有副作用的研究原型**：

- `EvidenceSnapshot`：仓库修改前后的内容指纹、require_changes/tests、由可信宿主定义的 required check IDs、当前/历史 TestEvidence、untracked 文件、允许的新增文件、未解决工作和致命基础设施错误；
- `CheckEvidence`：检查 ID、来源（CONTRACT / REPOSITORY / DIAGNOSTIC）、结果、对应的仓库内容指纹和递增序列；
- `evaluate_completion_candidate`：只输出 `NOT_READY`、`WRAP_UP_REQUIRED`、`CANDIDATE_READY` 和理由，**不返回 RunStatus，不修改仓库，不调用模型或隐藏 verifier**。

重要边界：
1. 测试来源必须由宿主可信数据定义，**不能由模型的工具参数或文本声明决定**。当前 Forge Test Tool 尚未提供可信 provenance；因此原型不能直接接入生产循环。
2. 即使 `CANDIDATE_READY`，也只能表示可以考虑结束或提交给独立 verifier，**不等价于任务功能正确或 SUCCESS**。
3. 当前算法只保守检查最新检查结果、证据快照和新增文件；未实现“测试覆盖充分性”“明确区分误写的自建测试与真正失败”以及真实 Git diff 影响范围证明。
4. 标记为 `REPOSITORY` 的测试是否真正可信，还需要固定原始测试文件版本、运行命令及 Task Contract；模型可能修改现有测试文件，**仅凭路径位于 tests/ 不足以证明可信**。
5. 标记为 `DIAGNOSTIC` 的失败不被直接忽略；如果同一内容快照后续同一个检查通过，前一次失败才可被替代。既不让一个自建失败永远锁死任务，也不把它悄悄删除。
6. 新增未跟踪文件既可能是临时文件，也可能是任务要求的新功能文件；只有宿主合同明确允许时才不再要求人工/宿主审查。

## 3. Pilot R1 状态的离线映射

下面的状态并非 Forge 运行时真正产生的事件，而是**把真实 Step 事件转化为拟议 EvidenceSnapshot 后的原型决策**：

| 时点 | 来源于 Pilot R1 Trace 的事实 | 原型给出的决定 | 不可推论的内容 |

| Step 13 | `typer/core.py` 被成功 `file_edit` 修改 | 无已验证通过测试时 `NOT_READY` | 不得断言补丁必然正确 |
| Step 16 | 新建 `repro_issue.py` | 新文件需要判断是否临时产物 | 不能仅凭名字自动删除 |
| Step 18 | `tests/test_core.py` 为 `27 passed`，`repro_issue.py` 仍存在 | `WRAP_UP_REQUIRED` | 不直接发出 SUCCESS |
| Step 22 | 自建 `test_tmp_fix.py`：2 failed、3 passed | 保留正式 focused PASS 与诊断 FAIL；`WRAP_UP_REQUIRED` | 不能认定这些失败必然无关 |
| Step 27 | 自建测试重测仍失败 | 按 unresolved evidence 处理 | 不自动忽略后续失败 |
| 外部验证 | Harbor Verifier F2P 1/1，P2P 22/22，reward 1.0 | **不进入 Agent 的 CompletionEvidence** | Hidden grader 不可泄漏给 Agent |

注意：两条 Pilot 特定测试明确构造了源文件已修改的抽象内容状态，并**假设** `tests/test_core.py` 是宿主确认存在的 repository 测试；当前原始 Trace 自身并不提供完整、不可伪造的 provenance 证明。这是原型输入前提，不是对现有 Forge Test Tool 的事实描述。

## 4. 当前生产行为的 3 个新测试（待完整环境运行）

追加在 `tests/test_agent_completion_guards.py` 的三个 **characterization** 用例分别检查：

1. Focused Test 通过后另一次 Diagnostic Test 失败，当前 `last_test_passed` 被覆盖，模型若 FINISH 可能收到 `LATEST_TEST_FAILED`；
2. 修复和测试后仍存在未跟踪 `repro_issue.py`，当前 Agent 内部 Guard 仍可能返回 SUCCESS；这**不**代表正式验收或自动 PR 交付应当成功；
3. 修复通过测试后重复只读检查，当前 No-Progress Guard 对“已验证而内容不变”状态不触发无进展反馈。

它们是**锁定现有语义的测试**，不是“将错误行为规定为长期正确”。当选定新的 Completion/Stop Contract 后，应该同步更新其预期。
