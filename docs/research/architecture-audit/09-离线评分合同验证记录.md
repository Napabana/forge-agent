## 2. 设计契约（研究候选，不视为已经采纳）

`TrialEvidence` 输入必须由**可信 Eval/Harbor 宿主**提供：是否真正开始模型请求、Agent Rollout 终态、故障归属（Model/Provider/Harness/TaskEnvironment/Cancellation）、Verifier 是否实际执行及结果、工作区快照是否存在、是否属于实验截止时刻内的快照。

`TrialDecision` 明确输出彼此独立的：

- `natural_finish`：模型是否自然提交 FINISH（且已开始真实模型调用）；
- `verifier_passed`：独立 Verifier 的原始结果（PASS/FAIL/未执行均保留）；
- `scoreable`：按试验开始前冻结的策略，当前行可否进入**该策略**的能力成功率分母；
- `scoreable_success`：仅 scoreable 行有布尔值，否则为 null；
- `failure_domain` 与 `rollout_status`：用于故障归因和报告。

`ScoringPolicy` 的显式开关包括是否评分 timeout/incomplete/gave_up 时的有效终态快照；原型用稳定 SHA-256 `policy_fingerprint` 绑定每行和聚合，防止以相同 policy 名称事后修改分母条件而混入旧结果。

**该策略本身不是 Harbor 官方评分协议。** 例如 Pilot R1 `timeout + reward=1.0`：在允许“deadline 内有效快照”的策略下可报告 `scoreable_success=True` 及 `natural_finish=False`；在仅评分自然结束的策略下，原始 `verifier_passed=True` 不变，但可能不进入该策略分母。应在实验前明确指标，不能按结果择优。

**尚未解决**：
1. 当前生产 `TrialResult` 没有可信的 `model_call_started`、`failure_domain`、`snapshot_within_deadline` 等字段。这些输入不能凭 `real_model_executed=True` 或错误消息正则猜测。
2. 对外部取消、Provider 429、有效快照时间点等，需要基于 Trace + Harbor 原生事件建立可信来源；不能让模型自报归属。
3. 模块的某些规则（例如非模型故障默认不可评分）是提议的**样本过滤政策**，不等于总 Trial 数可忽略：报告始终保留 `total_trials`、`scoreable_trials`、`unscoreable_trials`、`unscoreable_reasons` 和 `failure_domain_counts`。
4. 原型尚未和 Eval Factory/生产 CLI 的有效 Context/RepoMap/Test/Permission 配置对齐；这属于 H1。
5. 原型是单 Trial 评分合同验证，不提供任务轨迹回放、完整成本分析，也未对 Forge 实际生产代码行为产生改变。

## 3. 代表性确定性反例

| 场景 | 原型输出 | 不应该推断 |
|---|---|---|
| Agent FINISH + Verifier FAIL | scoreable=True, success=False | Agent 自报成功≠功能完成 |
| Agent TIMEOUT + Verifier PASS + deadline 内快照 | scoreable=True（策略允许时），natural_finish=False | 超时不等于自然 FINISH |
| Provider 错误，无 Verifier | scoreable=False，failure_domain=provider | 不应算作模型答错 |
| Runner/Harness 出错，未开始模型调用 | scoreable=False，reason=no_model_call_started | 不应算成模型训练能力 |
| Verifier ERROR 或 NOT_RUN | scoreable=False，success=null | “未评分”不等于 reward 0 |
| 没有有效截止时间内的快照 | scoreable=False，保留原始 verifier 观测 | 不能利用超出时限的修改取得成绩 |
| 同名策略变更“timeout 是否计分” | 聚合拒绝混用 | 不能事后更换统计口径 |
| 全部 Trial 不可评分 | success_rate=null | 不应输出 0% 代替无数据 |

离线聚合用例中有 4 条人为构造的 Trial：3 条可评分，其中 2 条成功，1 条 Provider 故障不可评分；原型同时输出总 Trial 数 4、可评分 3、成功 2、能力样本成功率 2/3、Provider 故障 1。**这是单元测试数据，不是 Forge 的实测成功率。**
