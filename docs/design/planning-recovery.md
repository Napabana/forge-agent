# 计划与执行恢复

## 为什么实现

计划让多步骤工作有明确状态，失败恢复把工具错误、语义停滞和基础设施故障转化为可检查的后续决策。

## 怎么使用

通过 `run --plan` 为该次运行启用结构化计划。`agent.planning_mode` 的内置默认值是 `off`，`auto` 根据明确的测试要求、多个文件线索或多步骤措辞判断是否需要计划。命令未指定 `--plan` 或 `--no-plan` 时使用配置值。未知副作用使用 Runtime 的 `recover` 命令处理。

## 怎样实现

`PlanningRuntime` 保存计划、步骤状态、修订和执行约束。`RecoveryRuntime` 分类失败、分配恢复预算，并决定收集证据、调整步骤或结束。`LoopDetector` 和语义进展跟踪识别重复动作和无效循环。

计划启用后仍可先用搜索、符号查找、文件读取及可识别的只读 Shell 查询做调查，再根据证据制定计划。门禁在可能修改仓库的动作前检查计划。测试断言失败可触发测试恢复，并在 Trace 中以独立的测试结论保留。

## 预期效果

模型能在有限预算内调整工作路径，用户能读到停止或重规划的原因。

## 使用边界

恢复建议只管 Agent 的下一步决策。已发出且结果未知的外部操作由持久化日志核对，变更操作不会自动重复。
