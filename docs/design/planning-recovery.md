# 计划与执行恢复

## 为什么实现

计划让多步骤工作有明确状态，失败恢复把工具错误、语义停滞和基础设施故障转化为可检查的后续决策。

## 怎么使用

按任务需求通过 `run --plan` 或 Agent 配置启用计划。用运行 Trace 查看计划版本、工具失败及恢复理由。未知副作用使用 Runtime 的 `recover` 命令处理。

## 怎样实现

`PlanningRuntime` 保存计划、步骤状态、修订和执行约束。`RecoveryRuntime` 分类失败、分配恢复预算，并决定收集证据、调整步骤或结束。`LoopDetector` 和语义进展跟踪识别重复动作和无效循环。

## 预期效果

模型能在有限预算内调整工作路径，用户能读到停止或重规划的原因。

## 使用边界

恢复建议只管 Agent 的下一步决策。已发出且结果未知的外部操作由持久化日志核对，变更操作不会自动重复。
