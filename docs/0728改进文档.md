# 0728 改进记录

## 改进目标

本轮只针对 `forge-agent-todo.md` 指出的四项核心能力做必要修改：

1. 完善 RepoMap 的语言包预加载、全量刷新、符号分类、重要性评分和 Agent 缓存失效。
2. 提高 TokenBudget 文本裁剪精度，并改进历史消息的预算选择。
3. 完善 LLM 调用的可重试错误分类、退避策略和流式输出失败边界。
4. 将 `_is_looping()` 升级为独立、增量、进展感知的循环检测与分级恢复机制。

## 修改约束

- 不修改与上述目标无关的模块。
- `agent/core.py` 保持同步 ReAct 主循环；不改变 `orchestrate_run` 的 async 边界。
- 不增加非必要依赖。
- 保留现有公开接口；新增行为优先通过带默认值或 keyword-only 参数提供。
- 只增加覆盖新行为和关键回归路径的必要测试。
- 每次代码或测试修改后，在本文档追加进度和验证结果。

## 实施规划

### 阶段 1：RepoMap

- 将仓库扫描拆为文件发现、语言预加载、文件解析三阶段。
- 同一次扫描对同一扩展名使用固定 parser 快照。
- 语言加载失败不再永久负缓存，支持强制刷新并生成结构化报告。
- 使用 class 祖先关系判断 method，避免按缩进误判顶层嵌套函数。
- 重要性评分加入符号、import、引用、路径和文件大小信号。
- 增加 Agent RepoMap 缓存主动失效入口。

### 阶段 2：TokenBudget

- 使用二分查找获得预算内更长的合法前缀。
- 将截断提示与正文作为整体估算，保证最终结果不超预算。
- 历史消息按对话单元选择，使用动态规划改进全局选择。
- 将消息协议和省略提示开销计入预算。

### 阶段 3：LLM Retry/Stream

- 在 LLM 层增加统一异常分类。
- 仅对白名单临时错误重试。
- 支持最大延迟、随机抖动和 `Retry-After`。
- callback 异常不重试；已经输出流式 chunk 后不自动重试，避免重复前缀。

### 阶段 4：LoopDetector

- 新增有界队列增量检测器，移除每步 EventLog 全量回放。
- 使用规范化 Action/Observation 指纹。
- 支持 AAA、ABABAB、ABCABCABC 周期。
- 使用 Observation、仓库状态和测试状态判断是否有进展。
- 第一次循环注入 Reflection，第二次循环才终止。
- 增加结构化循环事件与必要测试。

## 验收标准

- RepoMap 同次扫描 parser 选择一致，刷新后全量重扫。
- TokenBudget 输出相对于当前估算器严格不超预算。
- 流式调用不会因自动重试重复已输出内容。
- 循环检测不再逐步读取完整 JSONL，并能识别周期和进展。
- 相关定向测试和全量测试通过。
